# EchoLoom 一晚开发计划（本地 AI MV 流水线 + WebUI + 人工确认关卡，全自动开发）

## 无人值守总原则（最高优先级）
**人工确认关卡是产品功能，不是开发流程。** 开发全程由我自动推进：所有关卡我通过 API/浏览器自动化自行查看产物、自行确认放行（等于自测一遍关卡交互），**任何环节都不停下来等用户**；遇到问题修到成功（严格模式），直到产出优质成果物（可播放的完整 MV + 美观可用的 WebUI + 全绿测试）才算完成。用户唯一需要做的事：早上看结果。

## 交付目标
本地 Web 工作台（`python -m echoloom serve` 或 `scripts/start_all.ps1` 一键起 ComfyUI + 服务，localhost:8199）：
**分段流水线 + 四个人工确认关卡**——每个关卡产物可查看、可编辑、可换种子重新生成、可确认放行；全部确认后一键合成最终 MV。
同时保留 `python -m echoloom run --theme ...` CLI 直出片（自动放行关卡，共用同一 pipeline 核心，供自动化测试）。
产出 `output/<项目名>/`：MV mp4（烧 karaoke ASS，参数来自 UI）+ 母带整曲 + 分轨 + 全部中间产物（带版本历史）。

## 核心工作流（状态机，关卡驱动）
```
① 主题/歌词输入 → LLM 生成歌词草稿 → 【关卡A：歌词】编辑/重生成/确认
② 确认后 → LLM 生成 Music3 caption + 分镜脚本（每镜头：singer|scene、歌词段、画面prompt、时长、转场）
   → 【关卡B：分镜脚本】表格化编辑/重生成/确认
③ 确认后 → Z-Image 生成歌手肖像（默认 3 候选）→ 【关卡C：肖像】挑选/重生成/确认
④ 确认后 → Music3 生成整曲（默认中文歌 3 分钟）→ 【关卡D：音频】试听/换种子重生成/确认
⑤ 全部确认 → 最终合成（自动，无需看守）：
   分镜图(Z-Image，绑定已确认肖像形象) → H3 i2v 逐镜视频 → FaceFusion 对口型（歌手镜头）→
   Demucs 分轨 → 母带 → ASS 字幕（用 UI 调好的样式）→ ffmpeg 时间轴拼接+xfade+烧字 → mv.mp4
```
- 每个关卡产物带**版本历史**（v1/v2/…），重生成不动已确认版本，确认后锁存。
- 项目状态持久化（`state.json`），服务重启可续；进度 SSE 实时推送到 UI。
- 关卡支持「自动放行」开关（CLI/测试用；UI 默认人工确认）。

## 官方提示词格式（专门搜集确认，写成项目规范）
**`docs/prompt-formats.md` 作为权威规范，LLM 的 system prompt 与 few-shot 从它生成，测试断言 LLM 输出符合格式**：
- **Music3**：官方结构化 caption 格式（genre/mood/tempo/instrumentation/vocal 描述字段）+ 分段标签歌词（[Intro]/[Verse]/[Chorus]/[Bridge]/[Outro]）。来源：ComfyUI 官方文档与模板 `audio_minimax_music_3.json`、MiniMax 官方 caption rewriter 规则、本机 studebaker-gospel 已跑通的工作流实际参数（ground truth）。
- **H3 视频**：官方提示词规范（场景/主体/运动/镜头语言/光影结构化写法，含 `non_diegetic_music` 等字段的正确用法）。来源：Comfy-Org/MiniMax-H3 官方发布说明、本机 H3 工作流示例 prompt 与 custom_nodes README（H3-Turbo/TimelineDirector/Motion-Context）。
- 开发时先联网检索+读本地工作流交叉验证，两套格式确认无误后再写 LLM 模块；格式解析器配单元测试。

## 3 分钟时长（默认参数，冒烟实测打通）
默认**中文歌 180s**。本机节点标称 `max_duration` 上限 120s，但官方文档称最长 5 分钟，且核心含 AR 续写模块（ar.py）、studebaker 曾产出 2:15 成曲。M1 冒烟阶段实测两条官方路径：①节点直出 180s；②生成 120s + AR 续写延长。取官方推荐路径落地；仅在有实测失败证据时降级 120s 并在关卡D 明示。

## ASS 字幕样式编辑器（UI 可调 + 实时预览）
最终合成前 UI 提供「字幕样式」面板：字体/字号/加粗、主色、karaoke 高亮前色、描边色与宽度、阴影、对齐（默认底部居中）、边距、逐字/逐行、淡入淡出。参数改动 → 后端取一帧已生成分镜图+样例歌词，ffmpeg+libass 即时渲染预览图回显。样式存入项目，合成时套用；预置 2–3 套主题（暗夜霓虹/极简白/综艺描边）。

## 质量 & UI 美观保障
**TDD（红-绿-重构贯穿）**：状态机流转（关卡锁/版本/自动放行）、LLM 响应解析、Music3 caption 与 H3 prompt 格式校验（对齐官方规范）、分镜 schema、ASS 生成（\k 时间轴数学）与样式参数→Style 行映射、时间轴对齐、ffmpeg 命令构造（参数快照）、ComfyUI 客户端（mock 8188）、FastAPI 契约（TestClient：关卡 API/编辑/重生成/SSE/预览渲染）。真实模型调用走录制夹具 + `pytest -m smoke` 连真服务；端到端验收：API 驱动完整走一遍关卡→出片，断言产物/时长/字幕流。

**UI（taste-skill 自动循环迭代）**：按 taste-skill 定设计系统（暗色工作室风、字体/色板/间距），反模板脸；循环：实现→起服务→浏览器自动化截图（创建页/各关卡页/字幕样式页/进度页/成品页/窄屏）→按审美标准评审→修正再截，直至通过；截图存 `docs/ui-iterations/` 作过程证据。

## 一晚执行顺序（严格模式：失败修到成功，全自动直到产出优质成果物）
- **M0 环境（~1h）**：venv×2+依赖、Node、拷智谱 key、FaceFusion 模型下载、git init。
- **M1 冒烟+格式确认（~1.5h）**：起 ComfyUI → z_image 出图 → music3 出 30s 片段 → **实测 180s 两条路径** → ASR 转写 → 验证 8188 协议；联网+本地交叉确认 Music3/H3 官方提示词格式 → `docs/prompt-formats.md`。
- **M2 核心 TDD（~2.5h）**：状态机+8 步模块逐个红-绿实现；攻 H3 i2v API 格式工作流。
- **M3 服务与 UI（~2.5h）**：FastAPI 契约先行；前端各关卡页+字幕样式编辑器+预览；taste-skill 截图评审循环至美观通过。
- **M4 端到端（~1.5h）**：真实主题，我通过 API+浏览器自动化逐一确认关卡（歌词→分镜→肖像→音频）→ 最终合成出片成功；UI 交互路径全程浏览器再验一遍。
- **M5 交付（~0.5h）**：README、全测试绿、截图存档、git commit + 尝试 push（PAT 不通留命令）。

## 风险与对策
- **H3 i2v API 化**：有 API 样板与全部节点；TimelineDirector/Motion-Context 已装可调运动。
- **180s 时长**：两条官方路径实测优先；仅实测失败才降级 120s 并 UI 明示。
- **官方提示词格式**：官方文档+本机已跑通工作流双源交叉，格式不符在测试层拦截。
- **E 盘软链**：Z-Image 等权重软链 E:\工作流大全，需 E 盘在线（当前在线）。
- **关卡交互复杂度**：状态机 TDD 先行，UI 只做状态机的薄壳。
- **UI 迭代占时**：截图评审循环设轮次上限，未达美观标准不收尾。
- **push 失败**：不阻塞，留命令手动推。
